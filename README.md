# 未来はわからない。でも、考える材料はある。

過去のデータを集めて、分析して、AIとあれこれ考えて、見える形にする。  
そこで得た気づきも、知識として蓄えて、次の分析へ。

人もAIも未来を知っているわけではないけれど、「この先どうなる？」は考え続けられる。  
そんな仕組みをつくっています。

ここでは、その考え方と全体の構成を公開しています。

## 全体の構成

![情報収集、Hotakaによる基礎分析と推論基盤管理、AIの活用、可視化、ナレッジ化の領域と循環を示す概念図](architecture.svg)

Ⅱの基礎分析結果は、204からⅣの401へ直接渡して可視化します。ⅢでAIを活用して得た分析結果は、305から401へ渡します。

## Ⅰ 情報収集・蓄積

### 101  情報源

| 項目 | 内容 |
| --- | --- |
| 目的 | 先を考えるための材料を、確認できる情報源から得る。 |
| 仕組み | 確認できる情報源から、時点・対象・情報の意味を明らかにして材料を得る。<br>対象分野に応じた情報を、分析に使える材料として扱う。 |

### 102  情報収集部

| 項目 | 内容 |
| --- | --- |
| 目的 | 材料を継続的に集め、情報の不足や変化を把握できるようにする。 |
| 仕組み | 収集した情報を出典や時点と対応づけ、その意味を保って整理する。<br>材料の範囲や不足を把握し、分析に必要な情報を蓄積する。 |

### 103  情報記憶部

| 項目 | 内容 |
| --- | --- |
| 目的 | 取得した事実を、繰り返し分析に使える材料として残す。 |
| 仕組み | 材料を元の情報や出典と対応づけ、後から確認できる形で保持する。<br>取得情報と、後続の集計・解釈を分離して管理する。 |

## Ⅱ Hotaka｜基礎分析・推論基盤管理

### 201  EvaluationDate

| 項目 | 内容 |
| --- | --- |
| 目的 | 現在でも過去でも、その時点の材料から先を考えられるようにする。 |
| 仕組み | EvaluationDateを、分析に利用できる情報を定める基準時点とする。<br>過去時点の再現では、その時点で利用可能だった情報を材料とする。 |

### 202  分析材料の選択部

| 項目 | 内容 |
| --- | --- |
| 目的 | 情報の条件や違いを保ち、分析対象に合った材料を用意する。 |
| 仕組み | 対象・期間・属性・利用可能時点を確認し、分析目的に応じて材料を選ぶ。<br>対象や状況の変化を考慮し、意味の異なる情報を混同しない。 |

### 203  基礎分析部

| 項目 | 内容 |
| --- | --- |
| 目的 | 解釈や仮説の土台となる、条件の明確な分析基礎データを作る。 |
| 仕組み | 明示した対象・項目・条件に従い、定めた分析を行う。<br>比較や変化の把握に使う材料を整え、解釈や仮説とは区別する。 |

### 204  基礎分析結果記憶部

| 項目 | 内容 |
| --- | --- |
| 目的 | 各時点の基礎分析結果を残し、過去の比較、Ⅲへの受け渡し、Ⅳでの直接の可視化を可能にする。 |
| 仕組み | 基礎分析の出力を、評価基準日と分析条件に対応づけて保持する。<br>302へ分析材料として渡すほか、401へ直接渡して可視化する。Ⅲで導く解釈・仮説を含む分析結果とは区別する。 |

### H01  LLMモデル管理

| 項目 | 内容 |
| --- | --- |
| 目的 | 分析で使用するLLMと実行設定をHotaka側で管理し、目的に応じたモデルを利用できるようにする。 |
| 仕組み | モデルの選択・設定・稼働状態を管理し、モデル切替コマンドを通じて304のllama.cppへ切替を指示する。<br>切替結果と応答可能状態を確認し、実際に使用するモデルと実行条件を対応付ける。 |

### H02  KVキャッシュ管理

| 項目 | 内容 |
| --- | --- |
| 目的 | 推論の文脈に対応するキャッシュを管理し、再利用・退避・復元を制御する。 |
| 仕組み | Hotakaから304のllama.cppへ状態確認・退避・復元を指示し、結果を受け取る。<br>モデルの版・入力・実行構成と保存ファイルを対応付ける。キャッシュ本体のメモリ管理と保存・読込はllama.cppが担う。 |

H01・H02は[304の詳細構成](IMPLEMENTATIONS.md#ai-inference-detail)と同じ記号です。図の双方向矢印は、Hotakaからの管理指示と、304から返される状態・操作結果を示します。

## Ⅲ 発想・分析の指向｜問いと入力の構成

### 301  発想・分析の指向

| 項目 | 内容 |
| --- | --- |
| 目的 | 過去のデータを経験・材料として、何について先を考えるかを定める。 |
| 仕組み | 問い・仮説・着眼点を持ち込み、見る対象や関係を選ぶ。<br>対象の特性、組合せ、条件への適合、時間による変化などを考える。 |

### 302  分析条件の構成部

| 項目 | 内容 |
| --- | --- |
| 目的 | 発想を、AIへ渡せる明確な問いと条件にする。 |
| 仕組み | 材料・背景・判断の規則・進め方・出力形式・今回の問いを組み合わせる。<br>材料と問いの関係を明確にし、分析の前提を確認できるようにする。 |

### 302  入力構成の内訳

| 項目 | 内容 |
| --- | --- |
| 目的 | 共通の約束、対象固有の条件、今回の問いを分けて扱う。 |
| 仕組み | 分析の目的と共通の規則、対象に固有の条件を区別する。<br>背景となる材料と文脈、検討の進め方を整理する。<br>問いと求める結果の表現を明らかにする。 |

## Ⅲ AIの活用｜分析の実行と履歴

### 303  AIを活用した分析部

| 項目 | 内容 |
| --- | --- |
| 目的 | 材料と発想を結びつけ、その先を考える分析にAIを活用する。 |
| 仕組み | 材料・条件・問いをもとにAIで複数の見方や仮説を検討し、人の判断につなげる。<br>AIが未来を知っていることを前提にせず、材料から考えられる範囲を探る。 |

### 304  AI推論基盤

| 項目 | 内容 |
| --- | --- |
| 目的 | 分析の目的と前提に沿って、AIによる推論を支える。 |
| 仕組み | llama.cpp／llama-serverが選択したLLMを読み込み、材料と問いから応答を得る。<br>HotakaのH01・H02と連携し、モデル切替、KVキャッシュの状態確認・退避・復元を扱う。稼働中のKVキャッシュはホストのメインメモリに配置する。 |

### 305  分析結果記憶部

| 項目 | 内容 |
| --- | --- |
| 目的 | どの材料・問いから得た応答かを振り返り、次の検討へつなげる。 |
| 仕組み | 材料・問い・条件・応答を対応づけ、検討の経緯を保持する。<br>Ⅲの分析結果と、Ⅱで用意した分析基礎データを区別する。 |

## Ⅳ 可視化｜検討結果を知識につなぐ

### 401  可視化部

| 項目 | 内容 |
| --- | --- |
| 目的 | 材料・基礎分析・分析結果を、人が比較して検討できる形で示す。 |
| 仕組み | 204から基礎分析結果を直接受け取り、305から受け取るAIを活用した分析結果と共に、対象・期間・評価日を区別して表示する。<br>基礎分析結果の表示は、Ⅲの分析実行を前提としない。元の事実、集計値、仮説を含む結果を区別する。 |

### 401 → 501  可視化から検討結果の整理へ

| 項目 | 内容 |
| --- | --- |
| 目的 | 比較・検討した内容を、次の分析で再利用できる知識の材料にする。 |
| 仕組み | 表示結果に対する観察・解釈・仮説を、参照した分析結果とともにⅤへ渡す。<br>実際の結果と照合できる時点では、その差や適用条件も記録する。 |

## Ⅴ ナレッジ化・ベクトル化｜基礎分析への入力

### 501  検討結果の整理部

| 項目 | 内容 |
| --- | --- |
| 目的 | 検討から得た気づきを、根拠に戻って確認できる記録にする。 |
| 仕組み | 観察した事実・解釈・仮説を分け、対象・評価日・参照結果を記録する。<br>反例や未確認事項も残し、検討に至った経緯を辿れるようにする。 |

### 502  ナレッジ構成部

| 項目 | 内容 |
| --- | --- |
| 目的 | 検討結果を、条件を明示して再利用できる知識として整理する。 |
| 仕組み | 知見・根拠・適用条件・検証状態をひとまとまりにする。<br>知識の作成・更新時点を保持し、未検証の仮説と検証済みの知見を区別する。 |

### 503  ベクトル化・知識記憶部

| 項目 | 内容 |
| --- | --- |
| 目的 | 蓄積した知識を、意味の近い内容から検索できるようにする。 |
| 仕組み | ナレッジをベクトル化し、元の記述・根拠・適用条件と対応づけて蓄積する。<br>ベクトルの類似性と知見の妥当性は分けて扱う。 |

### 504 → 203  関連知識の検索・入力部

| 項目 | 内容 |
| --- | --- |
| 目的 | 関連知識を、Ⅱの分析対象・項目・条件の設定に活かす。 |
| 仕組み | 関連知識の根拠・適用条件・検証状態を確認し、分析条件として明示する。<br>過去時点の再現では、その時点で利用可能だった知識に限定する。 |
| 循環 | Ⅴ→Ⅱ→Ⅲ→Ⅳ→Ⅴ<br>Ⅰ 情報収集・蓄積　　Ⅱ Hotaka：基礎分析<br>Ⅲ 発想・分析の指向とAIの活用　　Ⅳ 可視化<br>Ⅴ ナレッジ化・ベクトル化と基礎分析への入力<br>Ⅰの情報を土台とし、Ⅴの知識をⅡの条件設定に活かして循環する。 |
